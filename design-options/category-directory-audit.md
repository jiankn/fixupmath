# 首页分类目录审计与改造

范围：`src/pages/index.astro` 的 `#all-calculators`，沿用方案 1 Fieldwork。

## 结论

旧版功能可用，但未达到本次视觉交付标准。主要问题是目录感过强、工具用途不清楚、不同数量的分类留下不均匀空白，以及手机双列拥挤。没有发现阻断工具访问的 P0 问题。

| 优先级 | 发现与用户影响 | 已实施改造 |
| --- | --- | --- |
| P2 | 三列分类的条目数量不同，纵向扫描跨越大块空白 | 一类一行；桌面左侧分类、右侧双列工具；平板标题在上 |
| P2 | 390px 手机双列分类，长标题拥挤，43px 链接行低于本项目 44px 触控目标 | 540px 以下单列工具，入口至少 84px；分类链接至少 44px |
| P2 | 只有工具名称，用户难以判断 Rebar、Board Foot 等工具的输出 | 每个入口复用注册表中的真实用途说明 |
| P2 | 筛选有结果时没有就近清除操作，分类缺少结果数量 | 新增清除筛选操作和实时分类数量；保留无结果提示 |
| P3 | 工具文字与次要文本层级接近，悬停仅改变文字颜色 | 深色半粗标题、次级说明、白色点击面；悬停底色和下划线；键盘焦点描边 |

## 保留的优点与实践

- 保留静态可访问链接、语义化列表和 h2/h3 层级；无需 JavaScript 也能浏览全部工具。
- 继续复用颜色令牌和深色主题，不新增图片、字体或依赖。
- 按分类阅读顺序布局，不用瀑布流打乱键盘顺序。
- 图标用于识别分类，橙色用于品牌和交互；避免为每个工具添加装饰图标。
- 说明文字完整显示，不截断；每个工具只有一个整块链接。

## 验证

- 浏览器检查：320 / 390 / 768 / 1440px，无页面横向溢出；390px 工具最小高度 84px。
- 搜索无结果、清除回到 30 个工具、Pool 筛选 2 个工具、gravel 文案搜索 2 个结果均正确。
- 键盘 Tab 到分类链接可见焦点；深色搜索与结果区域已目视检查。
- `npm run check`：0 errors、0 warnings；4 个现有 unused-import hints。
- `npm run build`：43 个页面成功生成。

当前为本地实现验收，不代表线上部署完成或完整 WCAG 合规认证。后续可用真实用户任务测试验证查找速度。
